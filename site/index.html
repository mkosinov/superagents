Меня зовут Максим Косинов. Я проектирую конвейер разработки, в котором LLM-агенты пишут и ревьюят код, а человек принимает решения в контрольных точках. Продукт — платформа для арт-студий: 1146 коммитов за четыре месяца. Конвейер работает сам: наблюдатели по расписанию разбирают задачи на четырёх машинах, человек подключается там, где решение действительно его.

Конвейер: две фазы, семь гейтов

Каждая фича проходит два этапа в двух разных средах. DESIGN — спека и план: наблюдатель по расписанию ведёт карточку сам и останавливается только там, где решение действительно за человеком. IMPL — автономный контейнер: код, ревью, тесты. Между фазами — только git и доска проекта. Нажмите на гейт, чтобы увидеть детали.

Доска проекта — живой прогресс

GitHub Project — единый источник правды о траектории. Статус карточки меняется ровно в момент гейта, никогда «по ощущению». Открыв доску, я вижу весь проект: что в работе, что ждёт моего решения, на какой машине.

Backlog → In Design → Ready to IMPL → In IMPL → PR (G7) → In-main → deployed

gate: concept / spec / plan / blocked

Метка на карточке: «ждём решения человека». Пустая метка — агенты работают, никого не ждут. Ответ человека стирает метку — конвейер едет дальше.

host: imac / macbook / hk / gcp

Какая машина ведёт карточку. Бюджет слотов на машину (imac — 2, macbook — 1); карточка на CI слот не занимает. Захват карточки — гонка, разруливается этим же полем.

Next Up 1–3

Явная очередь человека: что брать следующим. Когда первое в очереди смержено — очередь сдвигается сама, без ручного перекладывания.

Обе фазы оживляются наблюдателями по расписанию: DESIGN-наблюдатель каждые два часа берёт свободную карточку из Backlog, сверяет её с реальностью кода (устаревшие закрываются с доказательствами) и ведёт до первого стопа; IMPL-наблюдатель в контейнере подбирает готовые планы по свободным слотам своей машины. Человек заходит на доску — и видит картину целиком.

Четырнадцать ролей и панель ревью

Агенты — не «один чат с умной моделью», а разделение ролей с правами доступа. Контроллер не пишет код, ревьюеры не правят код, дорогие модели заняты только решениями, дешёвые — прогонами.

наблюдатели по расписанию

auto-design

Сессия на хосте, цикл каждые 2 часа: берёт свободную карточку из Backlog, сверяет с кодом и ведёт DESIGN до первого стопа — или до готового плана.

auto-impl

Скрипт в контейнере: подбирает карточки Ready to IMPL по свободным слотам своей машины и запускает IMPL-конвейер без человека.

контроллеры

@manager

Единая точка входа в контейнере: держит гейты, доску задач и scratchpad. Только он говорит с пользователем.

@architect

Исполнитель фазы: декомпозирует план и раздаёт задачи. Никогда не пишет код и не общается с пользователем — иначе перестаёт быть контроллером.

исполнители

@frontend-coder

Next.js и UI-код, строго по TDD: красный тест → реализация → рефакторинг.

@backend-coder

FastAPI: сервисы, репозитории, миграции. Тот же дисциплина TDD.

@debugger

Расследователь: ищет корневую причину, когда задача не идёт.

@tester

Дешёвая модель: готовит окружение и гоняет полные наборы тестов.

@docser

Пишет документацию фичи: PLAN.md, CHANGELOG.md — в ветку, до мержа.

скаут

Разведка до старта: read-only проход по коду, компактная сводка фактов, каждое утверждение — со ссылкой на файл и строку.

ревьюеры

@code-compliance-reviewer

Ступень 1: код соответствует утверждённому плану.

@code-quality-reviewer

Ступень 2: чистота кода и зелёные тесты; для UI — полный визуальный набор.

@plan-reviewer

Сверяет план со спекой до того, как план вообще начнут исполнять.

Принципы, которые держат качество

01

Контроллер никогда не пишет код

Архитектор раздаёт задачи и читает diffs. Как только контроллер начинает реализовывать сам, некому держать план.

02

Одна задача за раз

Исполнители работают строго последовательно. Параллельный диспатч агентов в одном worktree — источник конфликтов, который дороже ускорения.

03

Двухступенчатое ревью

Соответствие плану — отдельно, качество кода и тесты — отдельно. Одна ступень без другой пропускает либо drift, либо хрупкость.

04

Предохранитель: три цикла

Максимум три итерации «ревью → правки» на каждого ревьюера. Дальше — стоп и эскалация человеку, а не бесконечная возня.

05

Diff передаётся файлом

Ревьюер получает путь к patch-файлу, а не текст diff'а в промпте. Архитектор видит только статистику. Экономия ~30–40% токенов на ревью.

06

Решения живут в артефактах

Все правки ревью вносятся в текст спеки и плана, а не остаются в чате. Состояние проекта живёт в git и на доске: любая новая сессия — хоть человек, хоть наблюдатель — продолжает с того же места.

07

Дешёвое — дешёвым

Разведка, прогоны тестов, env — на младших моделях. Дорогая модель в главном окне занимается только решениями. Маршрутизация моделей — через собственный локальный шлюз.

08

Возврат — это нормально

Если код вскрыл ошибку спеки — траектория честно возвращается на гейт дизайна с комментарием, вместо того чтобы агенты «дожимали» неверный план.
